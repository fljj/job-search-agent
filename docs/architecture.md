# 当前架构设计

## 1. 架构目标

项目采用 FastAPI + React 的模块化单体架构。一个本机 Worker 处理数据库中处于运行状态的
BOSS、脉脉和猎聘 Run。脉脉 Run 只执行系统推荐扫描及获授权的同意/拒绝动作，
不进入通用消息发现和 Reply Router。猎聘已具备职位发现、消息处理及三类写动作执行能力；L5 真实页面
验收和明确授权前由默认关闭的发布开关阻止写入。外部平台、日历
和 LLM 通过适配器隔离；领域模块不直接操作页面。

核心不变量：

- 浏览器适配器只读页面或执行已经授权的命令；
- 硬性排除、动作权限、幂等和状态转换由确定性程序控制；
- LLM 不能直接点击页面、解除硬性排除或虚构候选人事实；
- 电话和面试具体时间必须进入人工确认；
- 所有外部写入都有策略决策、动作、尝试、证据和审计记录。

## 2. 当前目录

```text
apps/
  api/app/
    api/v1/                 # HTTP 路由
    core/                   # 配置、数据库和运行时依赖
    models/entities.py      # SQLAlchemy 模型
    schemas/                # Pydantic 请求/响应
    services/               # 应用编排、事务和持久化
  web/src/
    api/                    # HTTP 客户端
    pages/                  # 路由级懒加载页面
adapters/
  browser/                  # BOSS、脉脉和猎聘页面读取及动作适配
  calendar/                 # Apple、Google 日历适配
  llm/                      # 智谱、千问、Fake 适配器
packages/
  browser_worker/           # 浏览器命令、端口和规范化模型
  conversation_agent/       # Reply Router、记忆、草稿和回复策略
  job_parser/               # JD 规则解析与规范化
  knowledge_base/           # 可信事实检索
  policy_engine/            # 自动动作、资格、内容和状态机
  resume_selector/          # 站内附件选择
  scheduling/               # 电话、面试和日历领域逻辑
  job_matching/             # 硬过滤、精简 LLM 沟通决策和校验
scripts/run_agent_worker.py # 单 Worker 调度入口
tests/                      # 单元、浏览器夹具和 PostgreSQL 集成测试
```

## 3. 模块职责与依赖

依赖方向为 `api/worker → services → packages → ports`，适配器实现 ports。领域模块不能反向
依赖 FastAPI、SQLAlchemy 页面对象或具体模型供应商。

- `job_parser`：把外部 JD 转为受校验结构；规则解析先提供硬过滤所需字段。
- `job_matching`：硬过滤先行；未过滤职位由 LLM 判断是否建议沟通，程序验证结构、置信度和版本。
- `conversation_agent`：按 Rule → Knowledge → LLM → Human 路由回复并读取对话记忆。
- `policy_engine`：返回 `ALLOW_AUTO/REQUIRE_CONFIRMATION/DENY` 并校验动作状态转换。
- `resume_selector`：只选择已登记的平台既有在线简历或附件简历，不读取或上传任意本地文件。
- `scheduling`：识别电话/面试意图，查询日历但不自动承诺具体时间。
- `browser_worker`：定义页面输入输出；具体 DOM 逻辑位于 `adapters/browser`。
- `services`：负责用户归属、数据库事务、指纹、审计和跨领域编排。

## 4. 核心流程

### 4.1 主动职位

```text
职位列表 → 三态低成本预筛 → 唯一详情页快照 → 硬性排除
→ 必要的 LLM 解析 → 精简沟通决策 → 程序校验
→ 策略授权与幂等检查 → 动作执行、回读和审计
```

同一职位正文未变化时不重复打开或决策。模型熔断只暂停依赖 LLM 的队列，不阻塞
Rule/Knowledge 回复、明确卡片、对账和页面健康检查。
职位列表和消息关联职位中经过域名校验的详情链接会保存到 `jobs.source_url`。
主动招呼先查找已打开的唯一匹配页；找不到时才通过已保存链接打开目标，并重新
校验平台、外部职位 ID、公司、标题和招聘人后执行。链接失效或身份不匹配时
停止写入，不通过盲目刷新或重试绕过。

BOSS 职位发现创建的临时详情页在当前职位决策和主动招呼处理完成后关闭；主动招呼执行前
必须在该详情页再次核对外部职位 ID、公司、岗位和已规范化的招聘人身份。异常退出时仍由
`finally` 清理 Agent 自建页面，不关闭用户原有标签页。

猎聘职位发现只登记唯一 `c.liepin.com/` 首页为常驻 `JOB_LIST`。适配器按当前推荐顺序读取
卡片并滚动，不刷新首页，也不创建 `/zhaopin/` 页面。标题明确无关时直接记录跳过；相关或
不确定职位用 CDP 创建一个临时详情目标，核对职位 ID、公司和标题后读取完整 JD。猎聘企业
职位路径中的 `19 + 八位 ID` 与首页八位 `job_id` 归一为同一身份；`/a/` 猎头职位若首页公司
为明确脱敏名称，详情缺少可靠主公司时保留脱敏名称，只跳过公司强一致校验，职位 ID 和标题
仍必须一致。详情公司只读取主公司卡片，不得使用推荐职位卡片推断。每次只
保留一个 Worker 创建的详情页，完成沟通决策和获授权的“聊一聊”后再关闭；异常路径仍按页面
所有权清理。导入后的硬过滤、沟通决策、策略授权、动作队列和审计复用通用服务，明确猎头不得
产生主动招呼动作。

### 4.2 入站消息

```text
消息列表增量发现 → 导入入站和出站消息 → 身份与消息去重 → 读取岗位和对话历史 → 更新资格
→ Reply Router（Rule / Knowledge / LLM / Human）
→ 策略授权 → 动作执行与回读
```

增量发现之外，非终止会话按小时补扫平台原生同意卡片；身份不可靠的活动会话优先重查。
补扫只恢复读取机会，写操作仍受身份复核、策略授权和动作指纹幂等约束。
动作调度还会核对源入站消息之后是否已经存在平台出站消息；存在时跳过对应历史草稿，
避免本地记录缺失或服务重启后补发已经人工或自动回复过的内容。

明确索要简历、交换联系方式和地点卡片使用确定性规则，不调用 LLM。会话双方确认不合适后
进入终态，只有新岗位或明确重开表达才能开启新 episode。

回复前补职位沟通决策若遇到模型异常，进入统一 LLM 熔断；恢复后再继续 Reply Router 和
原有动作幂等流程。规则回复、知识库回复和明确平台卡片不依赖该决策。

猎聘的职位和消息共用唯一首页。每轮先读取消息抽屉并运行 Reply Router；本轮有新动作时将
抽屉保留到普通回复或投简历完成，再只关闭 Agent 本轮打开的抽屉，恢复首页后才允许职位
扫描。用户原本打开的抽屉保持不变；存在输入、弹窗、登录异常或无法恢复首页时停止本轮。
L3 生成的草稿持久化为不可派发，L4 不会补发；只有新入站消息或显式重新生成且再次通过
策略和页面复核的草稿可以进入 `ActionQueue`。

### 4.3 电话、面试和日历

```text
真实排期意图 → 资格门槛 → 标准化时间和时区 → 只读查询日历
→ 人工确认 → 用户批准/修改/拒绝 → 页面复核并发送 → 独立授权后写日历
```

电话至少需要 `ROUGH_MATCH`，面试必须 `FULL_MATCH`；日历空闲不等于用户接受时间。

## 5. Worker、Run 和页面所有权

- Worker 是本机唯一调度进程；Run 是某个平台的期望状态，二者不能互相推导。
- 平台会话只反映登录、页面和选择器可用性；动作能力另行展示。
- 常驻消息页和职位列表页通过 `browser_page_registrations` 声明角色和所有权。
- 临时详情页一次只打开一个，读取后关闭；不得关闭用户或其他角色的页面。
- 同角色多页面、登录失效、验证码、身份变化或选择器失效时暂停对应平台。
- BOSS 消息页和职位页不主动刷新；职位通过搜索标签切换和平台自身更新增量发现。
- BOSS 职位按配置的小批次读取，以外部职位 ID 去重；虚拟列表滚动后等待新卡片出现。旧职位重试目标不可见时记录退避，但本轮继续处理正常的新职位。
- 猎聘首页按小批次读取，以规范化职位 ID、跨 Run 发现记录、正文哈希和观察快照去重；
  招聘人身份单独规范化为猎头、企业招聘人或未知，明确猎头不产生主动沟通候选。招聘人暂时
  无法识别时仍保存有效职位供职位中心展示，但在重新取得可靠招聘人身份前禁止主动写操作。
- 猎聘到期失败重试每轮最多处理一条；非 LLM 详情重试完成后继续正常职位发现，不能让单条
  失败记录长期占用唯一发现名额。LLM 恢复类重试仍服从统一熔断，探针恢复前不继续业务。
- BOSS 列表缺少唯一职位 ID 时，只有招聘人、公司和职位摘要组成的复合身份全局唯一，
  且执行前再次核对目标公司或岗位，才允许写操作；否则继续降级并禁止写操作。

## 6. 浏览器适配器与策略引擎边界

所有写操作依次经过：身份核验、当前策略、`PolicyDecision`、幂等检查、动作原子占用、
写入前证据、执行、回读和审计。结果不可确认时进入 `OUTCOME_UNKNOWN`，只能只读对账，
禁止直接重发。

`adapters/browser/playwright_actions.py` 是当前真实 CDP 写执行器，不包含业务授权判断；
`fake_actions.py` 只用于测试。

浏览器选择器按平台存放在 `config/browser-selectors/`，每个平台文件独立维护版本、允许域名
以及 `session/job_list/job_detail/conversation/resume_action` 能力块。脉脉选择器文件仅作为平台页面配置载入，
运行时不创建普通消息适配器。加载器要求 BOSS、脉脉、
猎聘三个文件齐全且文件名与内部平台名一致，配置缺失、重复或结构无效时直接启动失败；页面
读取证据记录当前平台的选择器版本，而不是整套配置版本。猎聘 L4 复用真实 CDP 执行器、
`ActionQueue` 和既有审计状态机完成“聊一聊”、普通回复及现有简历投递。默认
`LIEPIN_WRITES_ENABLED=false` 在 L5 真实页面验收前阻止新猎聘草稿进入写执行；它不改变
L3 历史草稿的不可派发属性。

## 7. 数据、查询和审计

- PostgreSQL 是唯一业务数据库；ORM 变更必须配套 Alembic 迁移。
- 原始数据、规范化数据、职位观察和决策版本分开保存。
- 列表 API 在 SQL 中筛选、稳定排序和分页；总览使用独立聚合查询。
- 关键状态受数据库 CHECK 或唯一约束保护。
- 审计只追加，记录关联 ID、请求 ID、前后状态和原因码，不记录凭证或无必要全文。

## 8. 前端与部署边界

前端不自行决定发送权限。总览每 15 秒读取独立聚合与四层状态；状态码通过统一中文映射
展示，未知码保留原始代码；页面按路由懒加载。

API 默认绑定 `127.0.0.1`；非本机访问必须设置 `API_ACCESS_TOKEN`。招聘平台账号由用户
在专用浏览器手动登录，系统不保存账号密码。真实平台验证与正式数据库迁移必须单独授权。
