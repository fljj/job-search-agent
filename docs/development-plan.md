# 分阶段开发计划

## 1. 实施原则

- 严格按阶段交付，不提前连接真实招聘网站或开放发送能力。
- 每阶段先明确可验证验收标准，再实现最小必要范围。
- 外部服务通过适配器隔离，测试默认使用本地假实现。
- 任何自动发送能力都必须晚于只读接入和人工确认能力。
- 每阶段完成后更新相关专项文档，避免实现与规则脱节。

## 2. 第一阶段：职位策略和评分

### 范围

- 初始化 Python 3.12、FastAPI、Pydantic v2、SQLAlchemy 2、PostgreSQL、Alembic 和 pytest 后端工程。
- 初始化 React、TypeScript 和 Ant Design 前端工程。
- 建立候选人评分资料。
- 创建、查看、编辑、启用和停用多套求职策略。
- 配置工作模式、地点、薪资阶梯、行业规则和公司黑名单。
- 单条及批量导入模拟 JD。
- 使用规则解析 JD，并提供可选的大模型结构化解析接口和本地假实现。
- 实现硬性排除和 100 分评分引擎。
- 输出等级、资格状态、维度分、理由、风险和排除证据。
- 实现策略、导入、职位列表和评分详情页面。
- 编写完整评分单元测试及关键 API 集成测试。

### 明确不做

- 不连接 BOSS 直聘或脉脉。
- 不读取真实招聘会话。
- 不发送招呼语、消息或简历。
- 不接入日历。

### 实施顺序

1. 初始化项目与数据库迁移 → 校验：后端、前端和 PostgreSQL 可启动。
2. 实现候选人资料与策略模型 → 校验：完整策略可持久化和编辑。
3. 实现模拟 JD 导入与去重 → 校验：单条、批量和重复状态正确。
4. 实现 JD 解析及适配器边界 → 校验：无外部大模型仍可解析。
5. 实现硬性排除 → 校验：每条规则有稳定编码和正反测试。
6. 实现七维评分及解释 → 校验：总分、边界、版本和快照正确。
7. 实现 API 和前端页面 → 校验：用户可完成完整评分流程。
8. 完成自动化验证和 README → 校验：测试、类型检查和构建通过。

### 阶段验收

以 `product-requirements.md` 第一阶段验收标准和 `scoring-rules.md` 测试要求为准。

## 3. 第二阶段：知识库、招呼语和回复草稿

### 范围

- 建立带来源、敏感度和自动回复权限的候选人知识库。
- 管理多版本简历元数据及适用方向。
- 生成个性化招呼语。
- 对招聘方模拟消息进行多意图分类。
- 基于可信事实生成回复草稿。
- 计算回复置信度并检测敏感内容。
- 实现人工确认所需的决策数据，但不连接真实招聘网站发送。

### 阶段验收

- 不同 JD 生成有事实依据的差异化招呼语。
- 技术和经历问题可从知识库正确回答。
- 缺少事实时不虚构，并进入人工处理。
- 敏感内容和时间邀请不会被标记为允许自动发送。

## 4. 第三阶段：浏览器只读接入

### 范围

- 使用 Playwright 连接用户手动登录后的本地浏览器会话。
- 分别实现 BOSS 直聘和脉脉只读适配器。
- 读取当前职位页面和会话页面。
- 导入职位、招聘人和消息。
- 检测页面结构变化和身份不一致。
- 保存必要的结构化操作日志和页面证据。

### 明确不做

- 不点击发送消息。
- 不发送或上传简历。
- 不处理验证码或规避平台安全机制。

### 阶段验收

- 用户手动登录后可读取受支持页面。
- 页面结构异常时停止，不产生写操作。
- 重复读取不会重复导入职位或消息。

## 5. 第四阶段：人工确认发送

### 范围

- 实现待确认队列及确认卡片。
- 用户确认、修改后发送或拒绝招呼语和回复。
- 经确认后在网站内发送消息。
- 经规则允许后选择网站内已有附件简历。
- 实现操作状态机、执行前复核、失败处理和审计。

### 阶段验收

- 未批准动作无法执行。
- 修改内容后重新进行敏感和权限检查。
- 发送前核对平台、职位、招聘人和附件名称。
- 所有成功、失败、取消和过期操作可审计。

## 6. 第五阶段：安全自动沟通

### 范围

- 在开关允许时，对满足策略的 A 级职位自动招呼。
- 按置信度自动回复普通问题。
- 招聘方明确索要简历且全部条件满足时自动发送网站内附件。
- 实现限速、去重、异常停止和按平台暂停。
- 实现全局、策略和平台多层自动化开关。

### 阶段验收

- B/C 级和硬性排除职位不会越权自动沟通。
- 敏感问题无论置信度多高都进入人工确认。
- 相同招呼、回复和简历不会重复发送。
- 页面或身份异常时立即停止自动化。

## 7. 第六阶段：日历和面试安排

### 范围

- 识别电话、视频、技术和现场面试邀请。
- 解析明确或相对日期时间及其时区。
- 以只读方式查询日历并判断冲突。
- 根据工作时间、缓冲和通勤规则推荐候选时间。
- 创建时间确认任务。
- 用户确认后回复招聘方。
- 用户单独授权后创建或更新日历事件。

### 阶段验收

- 时间空闲时不会直接答应，而是创建确认任务。
- 时间冲突时生成两个或三个可用建议。
- 时间不明确时请求确认或澄清，不擅自选择。
- 未经用户确认不发送任何具体时间。
- 日历不可用时安全降级，不声称无冲突。

## 8. 跨阶段质量门槛

每个阶段至少完成：

- 领域单元测试。
- 关键 API 和数据库集成测试。
- Pydantic 输入输出校验。
- 数据库迁移验证。
- 后端类型检查和 Lint。
- 前端 TypeScript 检查、测试及生产构建。
- 安全边界和失败路径测试。
- 对应文档与实现同步更新。

未达到当前阶段验收标准时，不开放下一阶段的外部写操作。
