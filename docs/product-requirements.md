# 当前产品需求

## 1. 产品目标

`job-search-agent` 是在用户本机运行的无人值守求职辅助系统，正式写入能力面向 BOSS 直聘
和脉脉；猎聘当前处于 L2，只开放首页职位发现、硬过滤和评分，不发送招呼、消息或简历。
系统按用户策略发现职位、分析与评分、主动沟通、处理入站消息
并按条件发送平台已有简历。电话和面试具体时间、平台验证及安全异常始终由用户处理。

系统追求可解释、可审计和可恢复，不以绕过招聘平台限制或无限批量投递为目标。

## 2. 用户与可信资料

当前为单用户系统。候选人资料至少支持：

- 工作和管理年限、技能及技能来源；
- 行业经历、架构和核心系统经验；
- 学历、培养形式和可公开口径；
- 项目经历、到岗时间及允许自动引用的知识项；
- 平台内已有简历附件及默认附件。

候选人事实必须有用户录入、简历或明确确认来源。系统不得推测或虚构经历。知识项可启停、
设置敏感级别、有效期并保留版本。

## 3. 求职策略

用户可以创建、查看、编辑、启用和停用策略。策略支持：

- Java 后端、Java 开发、AI 应用开发（Java）、Vibe Coding、直播运营等岗位方向；
- Remote、Onsite、Hybrid 分别配置地点和优先级；
- 不同工作模式、币种和薪数的最低/期望薪资；
- 偏好行业、排除行业及公司黑名单；
- 是否接受兼职、猎头、实习、初级岗位；
- 全日制本科要求及候选人学历形式；
- 最快到岗回复口径；
- 主动沟通最低分，当前不得低于 80。

策略采用版本控制；评分和动作必须绑定实际使用的策略版本。全局、平台和策略级自动化配置
按最严格规则合并。

## 4. 职位发现、解析和评分

### 4.1 发现与去重

- 支持导入模拟 JD，并从 BOSS 职位列表和猎聘首页增量发现职位；
- BOSS 可轮换推荐、Java、区块链工程师等配置搜索入口，但不主动刷新页面；
- 猎聘只使用唯一首页，按当前推荐顺序滚动读取，不刷新首页、不打开独立搜索页；
- 先进行不消耗 LLM 的三态方向预筛，只有确定无关才跳过；
- 未知职位最多打开一次详情，保存正文内容哈希；正文未变化时不再重复打开或评分；
- 施工、绿化、客服、保险销售等在证据足够时应在预筛或硬过滤阶段停止，避免浪费 Token；
- 职位列表必须稳定分页并支持职位与消息关联跳转。

### 4.2 硬性排除

硬性排除必须先于 LLM 评分，由确定性程序执行，包括黑名单、明确完全无关方向、明确地点、
最低薪资、学历形式、实习/初级/兼职现场冲突等当前策略规则。工作模式、薪资或事实未知时
不得擅自硬排除，应记录风险并在沟通中确认。

### 4.3 LLM 评分

通过硬过滤的职位由当前配置的智谱或千问模型按七个受控维度给出 100 分评分：

- 岗位方向 15；
- 技术栈 25；
- 工作经历 15；
- 工作模式与地点 15；
- 薪资 15；
- 行业 10；
- 管理经验或岗位级别 5。

程序校验维度、总和、范围、证据、模型和提示版本。70 分及以上为 A，60–69 为 B，低于
60 为 C；等级不直接授权动作。主动招呼必须同时满足总分不少于 80、模型建议沟通、职位
有效、无硬阻断及策略授权。

输出包括总分、维度分、等级、匹配理由、风险提示、硬排除、动作阻断和证据。

## 5. 招聘沟通

### 5.1 主动沟通

满足主动沟通条件时，系统可自动发送 BOSS 平台默认招呼。猎聘 L2 只记录候选资格，不创建
招呼草稿或动作。猎头岗位
是否主动沟通服从策略和分数封顶；不得只因对方是猎头而把岗位方向判为不匹配。

### 5.2 入站消息

招聘方主动发来的消息优先于职位列表处理。系统应增量扫描 BOSS 和脉脉真实消息，并在消息
中心展示平台、招聘人、关联岗位、资格、最新消息、草稿来源和动作状态；广告机器人和脉脉
系统推荐不作为普通消息展示。

回复使用固定路由：

1. Rule Reply：到岗、薪资、地点、工作模式和明确平台卡片；
2. Knowledge Reply：自我介绍、技能、项目和管理经验；
3. LLM Reply：需要理解上下文的开放式沟通；
4. Human：电话或面试具体时间。

回复前读取当前 episode 的结构化记忆和最近对话，避免重复询问已经确认的问题。模型不可用时
Rule/Knowledge 和明确卡片仍应运行；开放消息等待模型恢复，不伪装成人工确认。

### 5.3 简历和原生卡片

- 招聘方明确索要简历时，不受主动职位评分门槛限制；只要没有已证实硬阻断、身份可靠、
  附件可用且未发送过，即可发送平台默认简历；
- “已查看简历”或仅提及“简历”不是发送请求；
- 交换联系方式卡片在资格至少大致匹配时直接同意；
- 工作地点卡片按当前策略判断，允许地点可直接接受；
- 脉脉系统推荐只做低成本相关性判断：明显无关或保险销售拒绝，大致相关可同意发送资料；
- 所有原生卡片使用确定性规则，不调用 LLM。

### 5.4 终态与婉拒

职位或对话有明确不匹配证据时可以礼貌拒绝。用户或招聘方已经明确结束沟通后必须保存终态
证据，列表轮询不再打开或回复；只有新岗位或明确重新沟通表达才能开启新 episode。

## 6. 电话、面试和日历

- 只有明确电话/通话/面试表达才进入排期逻辑，“交流一下”属于普通沟通；
- 电话沟通至少需要 `ROUGH_MATCH`，面试必须 `FULL_MATCH`；
- 没有充分了解岗位时禁止约面试；
- 任何电话、视频或现场面试具体时间都必须用户确认；
- Apple Calendar 为 macOS 默认供应商，Google 可配置，Mock 只用于测试；
- 日历空闲不能自动接受时间，日历写入必须独立授权并具备幂等性。

## 7. 无人值守运行

- 一个 Worker 处理全部运行中的平台 Run；Worker、Run、平台会话和动作能力独立展示；
- 页面被关闭或会话恢复后可以通过控制台重连，但多页面歧义时不得猜测目标；
- 职位和消息页面不主动刷新，避免登录状态失效；
- LLM 认证、余额、限流或服务故障打开能力熔断，只暂停依赖模型的任务；
- 熔断探测先单飞，失败后按 60 分钟持续探测，用户可以手动重试；成功后恢复模型队列；
- 不设置小时或每日投递配额；公司和招聘人冷却只用于防重复；
- 验证码、登录验证、页面身份变化或选择器失效时暂停对应平台并提示用户。

## 8. 安全、幂等和审计

- 浏览器写操作必须经过策略授权、服务端身份复核和动作状态机；
- 消息、职位、草稿、动作、简历、推荐和日历写入均需幂等；
- 结果不可确认时进入 `OUTCOME_UNKNOWN`，先只读对账，禁止直接重发；
- 审计记录输入版本、决策、目标、动作、尝试、证据和结果；
- 不保存招聘平台账号密码，不记录 API Key、Cookie 或无必要的敏感页面全文；
- 不实现验证码破解、指纹伪装、代理池、反检测或无限制批量投递。

## 9. 控制台

当前页面包括：

- 总览：全局计数、Run、Worker、平台会话、能力和恢复入口；
- 职位中心：稳定分页、筛选、评分、硬性规则、风险及沟通联动；
- 消息中心：跨平台对话、岗位、资格、草稿来源和动作结果；
- 候选人资料：资料、知识项和平台附件；
- 求职策略：常用字段和完整策略编辑；
- 面试确认：真实排期请求及日历冲突；
- 系统设置：LLM、自动化开关、Run 和审计状态。

内部状态必须使用统一中文展示；未知状态显示中文说明并保留原始代码。列表总数来自独立 SQL
统计，不得用当前页长度冒充全量数据。

## 10. 验收标准

- 硬性排除和七个评分维度有完整边界测试；
- Rule/Knowledge 回复在 LLM 不可用时仍能工作；
- 主动沟通 80 分边界、入站简历、资格和终态不会互相混用；
- 电话/面试具体时间不能绕过人工确认；
- 重复扫描、失败重试、未知结果和 Worker 重启不产生重复外部动作；
- PostgreSQL 迁移可从空库完整升级，列表分页稳定；
- BOSS 和脉脉使用脱敏夹具回归，真实平台测试单独授权；
- 后端测试、类型检查、Lint、前端测试和生产构建通过。
